# طراحی مرحله‌ای حسابداری پیشرفته (وضعیت: طراحی — فعال نیست)

**اصل:** این بسته با سیستم مالی فعلی (فاکتور/پرداخت/`ledger_entries`/حساب مشتری) *موازی* است و **به آن وصل نیست**. هیچ مهاجرت، تریگر یا Route در کد اجرایی ۱٫۷۵ برای آن وجود ندارد. وصل‌کردن فقط با تأیید صریح مدیر مالی مرحله‌به‌مرحله انجام می‌شود.

## فایل‌ها
- `001_chart_journal.proposed.sql` — جدول‌ها: `coa_accounts` (سرفصل‌ها)، `journal_entries` / `journal_lines` (سند و خطوط)، تریگر تراز بودن (deferred)، تغییرناپذیری اسناد پست‌شده، و گزارش‌ها: `v_trial_balance` (تراز آزمایشی)، `fn_income_statement` (سود و زیان)، `fn_balance_sheet` (ترازنامه)، `fn_cash_flow` (جریان وجه نقد، روش مستقیم). این فایل در `test/accountingDesign.test.js` روی PostgreSQL واقعی اعمال و با دادهٔ نمونه راستی‌آزمایی می‌شود (تراز بودن، رد سند نامتوازن، معادلهٔ حسابداری، تغییرناپذیری، سند معکوس).

## سازگاری با دفتر کل فعلی
دفتر فعلی «دفتر حساب مشتری» (یک‌طرفه، مانده = جمع) است؛ حسابداری دوطرفه یک لایهٔ بالاتر است. نگاشت پیشنهادی (قابل بازتولید از اسناد موجود، بدون تغییر آن‌ها):

| رویداد موجود | سند دوطرفه |
|---|---|
| فاکتور (مبلغ کل) | بدهکار «حساب‌های دریافتنی ۱۱۰۳» / بستانکار «درآمد فروش ۴۱۰۱» (تخفیف: بدهکار «تخفیفات ۴۱۰۲») |
| پرداخت نقدی / کارت | بدهکار «صندوق ۱۱۰۱» یا «بانک ۱۱۰۲» / بستانکار «دریافتنی ۱۱۰۳» |
| برگشت پرداخت | معکوس سند پرداخت |
| هزینه | بدهکار «هزینه‌ها ۵xxx» / بستانکار «صندوق/بانک» |
| ابطال فاکتور / تعدیل | سند معکوس (هرگز ویرایش/حذف) |
| اعتبار مشتری (اضافه‌پرداخت) | بستانکار «پیش‌دریافت از مشتریان ۲۱۰۱» |

## مراحل پیشنهادی
1. **(انجام‌شده — طراحی + تست SQL)** مدل داده و گزارش‌ها، بدون اتصال.
2. **حالت سایه (Shadow):** پس از تأیید مدیر، یک کار پس‌زمینه اسناد موجود را با نگاشت بالا به journal منعکس می‌کند و هر شب «جمع دفتر کل مشتریان ≟ مانده دریافتنی ژورنال» را گزارش می‌دهد؛ هیچ تصمیم مالی از آن گرفته نمی‌شود.
3. **سوییچ:** پس از ≥ ۳ ماه تطبیق صفر-مغایرت و تأیید مدیر، گزارش‌های رسمی از ژورنال خوانده شوند (پرچم `accounting_enabled` در تنظیمات، پیش‌فرض خاموش).
4. **بستن دوره و سال مالی** (سند بستن حساب‌های موقت به سود/زیان انباشته) — نیازمند تصمیم تقویم مالی (شمسی) و سیاست استهلاک/موجودی؛ تصمیم کسب‌وکار است و پیاده‌سازی نشده.

## تصمیم‌های بازِ نیازمند مدیر
سرفصل‌های استاندارد (کد حساب‌ها)، تقویم مالی، شناسایی درآمد (هنگام فاکتور یا هنگام دریافت)، بهای تمام‌شدهٔ کالا (FIFO/میانگین)، مالیات بر ارزش افزوده، مبنای تعدیل ارز/تورم.
