# کافینو | CAFINO — نسخه دسکتاپ ویندوز (Electron)

## ساختار پوشه
```
electron-app/
  package.json
  main.js
  app/
    index.html
    bundle.js
```

## مراحل ساخت فایل نصب (.exe) روی ویندوز خودت

> پیش‌نیاز: نصب بودن **Node.js** (نسخه ۱۸ به بالا) روی ویندوز — از nodejs.org دانلود و نصب کن.

۱. این پوشه‌ی `electron-app` رو کامل روی ویندوزت کپی کن.

۲. یک Command Prompt یا PowerShell باز کن و به داخل پوشه برو:
```
cd مسیر\پوشه\electron-app
```

۳. پکیج‌ها رو نصب کن:
```
npm install
```

۴. برای تست سریع (بدون ساخت exe)، فقط اجرا کن:
```
npm start
```
برنامه توی یه پنجره‌ی دسکتاپی مستقل (بدون نوار آدرس مرورگر) باز میشه.

۵. برای ساخت فایل نصب واقعی (.exe):
```
npm run dist
```
بعد از چند دقیقه، داخل پوشه‌ی `dist` یه فایل مثل `کافینو CAFINO Setup 1.52.0.exe` ساخته میشه. همین فایل رو اجرا کن تا برنامه مثل هر نرم‌افزار دیگه‌ای (با میانبر دسکتاپ و منوی استارت) نصب بشه.

## نکات مهم

- **فونت:** فونت پیش‌فرض برنامه Vazirmatn است و داخل خود برنامه (`app/fonts/`) همراه مجوز OFL آمده؛ نیازی به نصب جداگانه ندارد و آفلاین هم کار می‌کند. کاربر همچنان می‌تواند از تنظیمات ← ظاهر فونت دلخواه خودش را بارگذاری کند.
- **دیتا کجا ذخیره میشه؟** چون برنامه از localStorage استفاده می‌کنه، اطلاعات داخل پروفایل کاربری ویندوز ذخیره میشه (مخصوص همون نصب). اگه برنامه رو Uninstall کنی، معمولاً دیتا پاک نمیشه ولی توصیه میشه قبلش از بخش گزارش‌ها خروجی اکسل بگیری.
- **آیکون اختصاصی:** اگه یه فایل `icon.png` (حداقل ۲۵۶×۲۵۶) به مسیر `electron-app/app/icon.png` اضافه کنی، خودش توی build بعدی به‌عنوان آیکون برنامه استفاده میشه (کد از قبل آماده‌ست).
- **آپدیت بعدی برنامه:** هر وقت فایل `App.jsx` رو بروزرسانی کردم، کافیه فایل‌های جدید `index.html` و `bundle.js` رو جایگزین همون فایل‌ها توی `electron-app/app/` کنی و دوباره `npm run dist` بزنی.
- این ساخت exe باید **روی خود ویندوز** انجام بشه (نه لینوکس)، چون electron-builder برای پکیج‌کردن نصب‌کننده‌ی ویندوزی به ابزارهای ویندوزی نیاز داره.

## اتصال به سرور
رابط برنامه گزینهٔ سرور ندارد. برای فعال‌کردن، `app/config.js` را ویرایش کنید:
`window.CAFINO_CONFIG = { apiBaseUrl: "https://api.example.com", cafeId: "" };` (خالی = حالت محلی).

## مرکز چاپ و اسکن (نسخهٔ ویندوز)

در برنامه: «ابزارها ← پرینت و اسکن ← مرکز چاپ و اسکن».

- **چاپ مستقیم**: PDF و تصویر (PNG/JPG/BMP) با `pdf-to-printer` (SumatraPDF) روی پرینتر ویندوز چاپ می‌شود. پس از `npm install` این پکیج نصب می‌شود. تعداد «چاپ‌شده/ناموفق» از صف چاپ ویندوز (PowerShell `Get-PrintJob`) خوانده می‌شود و فقط صفحات واقعاً چاپ‌شده صورتحساب می‌شوند.
- **اسکن**: با WIA ویندوز (PowerShell). فایل‌ها در `Documents\CAFINO-Scans` ذخیره می‌شوند. اسکنرهایی که فقط TWAIN دارند در WIA دیده نمی‌شوند؛ برای آن‌ها از «ثبت دستی» استفاده کنید.
- **کنتور پرینتر**: «خواندن از دستگاه» فقط برای پرینتر شبکه‌ای با IP و SNMP روشن است (کنتور استاندارد `prtMarkerLifeCount`). برای پرینترهای USB کنتور را روی دستگاه بخوانید و در برنامه وارد کنید.
- ⚠ این بخش روی لینوکس تست خودکار شده (منطق، پل IPC با شبیه‌ساز، رابط)؛ اجرای واقعی PowerShell/WIA/SNMP روی ویندوز و مدل پرینتر شما باید یک‌بار امتحان شود.

## امنیت نسخهٔ دسکتاپ (از ۱.۷۱.۰)

| موضوع | رفتار |
|---|---|
| ارتباط دستیار هوشمند (`cafenet:fetch`) | فقط میزبان‌های مجاز: `api.openai.com`، `api.anthropic.com`، `generativelanguage.googleapis.com`، `openrouter.ai`، `api.groq.com`، `api.deepseek.com`، `api.mistral.ai`، `api.together.xyz`، `api.x.ai`، `api.perplexity.ai`. میزبان دیگر (n8n، Ollama، سرور خودتان) فقط وقتی کار می‌کند که در **پنجرهٔ تأیید ویندوز** «اجازه می‌دهم» را بزنید؛ انتخاب شما در `net-allow.json` (پوشهٔ دادهٔ برنامه) می‌ماند. مدیر IT می‌تواند میزبان‌های ثابت را با متغیر محیطی `CAFINO_FETCH_HOSTS=host1,host2` بدهد. ریدایرکت، هدرهایی مثل Cookie/Host، بدنهٔ غیرمتنی و پاسخ بیش از ۵ مگابایت رد می‌شود. آدرس‌های link-local و metadata ابر (`169.254.x.x`) هرگز مجاز نیستند؛ لوپ‌بک/شبکهٔ داخلی (مثل Ollama) فقط با تأیید شما. |
| کنتور پرینتر (SNMP) | فقط IP خصوصی (۱۰/۸، ۱۷۲.۱۶/۱۲، ۱۹۲.۱۶۸/۱۶)، فقط پرینتری که در فهرست پرینترهای ویندوز با همان IP هست یا شما در پنجرهٔ تأیید پذیرفته‌اید؛ حداکثر ۶ درخواست در دقیقه برای هر IP و ۱۰ IP متفاوت در ۱۰ دقیقه (ضد اسکن شبکه). |
| پل IPC | هر درخواست فقط از «فریم اصلی» صفحهٔ خود برنامه (`file://…/app/`) پذیرفته می‌شود، نه iframe یا صفحهٔ بیرونی. |
| رازها | کلید API هوش مصنوعی با `safeStorage` (ویندوز DPAPI، macOS Keychain، لینوکس libsecret) رمز و در `…/secure/` ذخیره می‌شود. فقط نام‌های ثابت پذیرفته می‌شود. |
| مهر یکپارچگی | هش دادهٔ مالی با `safeStorage` ذخیره می‌شود؛ ویرایش بیرونی داده وقتی برنامه بسته است هنگام باز شدن هشدار می‌دهد. |
| ابزار توسعه‌دهنده | در نسخهٔ نصبی بسته است (برای عیب‌یابی: متغیر محیطی `CAFINO_DEVTOOLS=1`). |

### محدودیت‌های صادقانه
- ذخیرهٔ امن سیستم‌عامل جلوی کدی که با **همان حساب کاربری ویندوز** اجرا شود را نمی‌گیرد؛ جلوی کپی‌کردن فایل‌ها، دیسک دزدیده‌شده و ویرایش دستی را می‌گیرد.
- داده‌های اصلی در حالت محلی هنوز در حافظهٔ Chromium (localStorage) است؛ «مهر یکپارچگی» فقط **آشکارسازی** است، نه جلوگیری. برای حسابداری که باید در برابر دستکاری مقاوم باشد از **حالت سرور** (PostgreSQL + لاگ حسابرسی زنجیره‌ای هش + تراکنش) استفاده کنید. مهاجرت حالت محلی به SQLite در این نسخه انجام نشده است.
- در لینوکس بدون libsecret/kwallet (و در برخی محیط‌های بدون ورود گرافیکی) `safeStorage` در دسترس نیست؛ برنامه در این حالت مثل قبل کار می‌کند ولی کلید را رمز نمی‌کند.
- این سازوکارها فقط در اجرای واقعی Electron روی ویندوز قابل بررسی نهایی‌اند؛ منطق آن‌ها با تست خودکار پوشش داده شده، ولی پنجرهٔ تأیید و DPAPI روی ویندوز واقعی در این محیط اجرا نشده است.
